HOW TO INTERPRET
- Skewness near 0 and a Q-Q line close to straight mean the column is now close to normal.
- A normality test (normaltest_p in the csv) almost always rejects with thousands of rows, even for tiny deviations; judge by skewness and the Q-Q plot instead of the p-value alone.
- Extreme values lose influence: the largest z-score and the outlier count drop because the long tail is pulled in.
- Box-Cox picks the best power automatically, so it usually normalises at least as well as the fixed log; log is simpler to explain ('a 10% increase') and needs no fitted parameter.
- Both need positive values, so a column with zeros or negatives is shifted first (shift_used in the csv).
- A transformation cannot make a flat (uniform) or multi-peaked column bell-shaped. Skewness can improve only because a few outliers were pulled in, while the main body stays flat: always look at the histogram and the Q-Q plot, not only at the skewness number.
- Log and Box-Cox only fix RIGHT skew. For left-skewed data reflect it first (max + 1 - x) or use Yeo-Johnson, which accepts any values.
- Careful with the target relationship: correlation with the target can go up or down (see corr_with_target in the csv); check that the transformed version really helps your model.
- For modelling, fit the lambda on TRAINING data only (sklearn PowerTransformer(method='box-cox') inside a Pipeline), and apply the SAME lambda to the test data. This script fits on all rows only to describe the effect.
