WHAT TO TAKE FROM THIS
- KNN with cosine distance ignores row length by definition, so normalizing first changes nothing for it; KNN with euclidean distance on L2-normalized rows ranks neighbours exactly like cosine distance.
- Euclidean KNN scores 0.555 on L2-normalized raw rows versus 0.918 on raw rows and 0.512 when only the columns are standardized.
- Normalizing RAW rows lets the biggest columns (e.g. ram) dominate the direction of the row; standardizing the columns first gives every feature a fair vote.
- L1 is the most gentle (less affected by one huge value), L2 is the standard for text and cosine similarity, Max is simple but one outlier decides the whole row.
- Row normalization throws away the size of the row. If size carries the signal (big specs = expensive phone) the scores drop; if only proportions matter (word counts, spectra) it helps.
- Tree models and (mostly) linear models do not need row normalization; use it for distance- and angle-based methods (KNN, SVM, K-Means, text models).
- Everything above was evaluated with the normalizer inside the cross-validation pipeline (Normalizer has nothing to learn, but the StandardScaler in front of it is fitted on the training rows only).
